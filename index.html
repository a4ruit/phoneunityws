Required stuff:

An empty 3D Unity project
A VSCode folder
Existing GitHub Account

What we will learn:

The workflow process on how we can use WebSockets to drive interactions in Unity so that you can walk away with a foundation to tinker around with.

Part 1 — Setup

Goal: your phone talking to Unity through your own free server.

(a) Put the site online

Get the VSCode folder onto GitHub, then deploy it free on Render to get an https://…onrender.com address.

GitHub

At github.com/new make a repo, then Add file → Upload files and drag your folder in. Commit. No commands needed.

Render

At render.com: New → Web Service, pick that repo. Build npm install, Start node server.js. Wait for Live.

(b) Open it on your phone

Visit that address, tap Start, allow motion access. HTTPS is what lets the phone share its sensors.

(c) Point Unity at it

In the HeadingReceiver component, set the server to wss://…onrender.com/ws, then press Play.

You'll know it works when…

You turn your phone and the view turns with you in Unity. That's the whole pipe — everything else is tinkering.
